Node Partition Topology Coordinator deployed.

Controller: {{ include "nodepartition.fullname" . }}-controller
Driver name: {{ .Values.driverName }}
Partition mode: {{ .Values.partitionMode }}

The controller watches ResourceSlices from all DRA drivers and publishes
coordinator-managed DeviceClasses with opaque PartitionConfig data. The
webhook expands partition ResourceClaims into driver-specific requests.

Check the controller and webhook Service:

  kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "nodepartition.fullname" . }}-controller
  kubectl -n {{ .Release.Namespace }} get service/{{ include "nodepartition.fullname" . }}-webhook

List generated partition and grouping classes:

  kubectl get deviceclasses -l nodepartition.dra.k8s.io/managed=true

List curated offerings (aggregate classes with `offering: "true"`):

  kubectl get deviceclasses -l nodepartition.dra.k8s.io/offering=true

Topology-rule and device-grouping ConfigMaps are trusted in
{{ .Values.controller.configNamespace | default .Release.Namespace }} by default.
Set `controller.watchAllNamespaces=true` only when every namespace that can
create a labeled ConfigMap is trusted.

The webhook fails closed for ResourceClaim transport errors and uses best-effort
transport handling for Pod and VMI rewrites. Metrics are available at
`http://<controller-pod>:{{ .Values.controller.healthPort }}/metrics` while
`controller.metrics.enabled=true`.

If running more than one coordinator release in a cluster, use a unique
`driverName`, non-conflicting grouping names, and a unique
`controller.leaderElection.id` value.
DeviceClasses are cluster-scoped; changing `driverName` requires removing the
old release's managed classes before installing under the new identity.

The default TLS mode uses cert-manager and expects the configured
{{ .Values.controller.webhook.tls.certManager.issuerKind }}
{{ .Values.controller.webhook.tls.certManager.issuerName }} to already exist.
